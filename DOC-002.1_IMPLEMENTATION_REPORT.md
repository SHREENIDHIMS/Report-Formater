## Docker validation

The worker was built with:

    docker build -t vtu-report-studio-renderer:doc0021 \
      -f apps/api/worker/rendering/Dockerfile apps/api

Every corpus run used:

- --network=none
- --read-only
- private --tmpfs /tmp:rw,nosuid,nodev,noexec,size=64m
- --cap-drop=ALL
- --security-opt=no-new-privileges
- --memory=512m
- --cpus=1
- --pids-limit=128
- read-only DOCX input mount
- private writable job-output mount

Observed results:

- Real LibreOffice conversion succeeded for all seven fixtures.
- PDFs opened successfully with PyMuPDF.
- Page metadata and text were extracted successfully.
- Fresh-container re-render comparison passed for all seven fixtures.
- Successful worker jobs retained only input.pdf; copied DOCX and LibreOffice
  profile were removed.
- Source SHA-256 remained unchanged.
- The image runs as UID 10001.
- Root filesystem is read-only; only the mounted job directory is writable.
- Network probe failed as expected under --network=none.
- An unmounted /etc/hosts path was not treated as a valid DOCX.
- Macro-containing OOXML is rejected before LibreOffice by the shared package
  validator and a dedicated automated test.

Timeout handling remains covered deterministically at the subprocess boundary
by the rendering unit test. A real timeout was not forced against LibreOffice
because that would require a nondeterministic pathological document; the
container wall-clock and subprocess timeout controls are present.

## Health-test investigation

The original TestClient health test hung on this Windows environment. The hang
was not caused by the route: a trivial asyncio.run() also stalled under the
environment's Proactor event-loop behavior, and the synchronous TestClient path
never completed.

The health endpoint performs no asynchronous I/O, so it was made synchronous
and the test now calls the endpoint function directly. This avoids a
platform-specific test harness deadlock while still verifying the exact health
response. The full suite now completes.

## Limitations and unverified items

- Visual comparison uses deterministic page-image hashes for this pinned image
  and font set. It does not prove pixel identity with Microsoft Word.
- The corpus does not yet include OMML equations, tracked changes, comments,
  floating shapes, or embedded OLE objects. DOC-001 continues to classify
  those constructs before transformation.
- The container does not yet have queue/API integration, signed URLs,
  object-storage persistence, or production job authorization.
- Docker resource flags are validated in this local run; production policy
  still needs deployment-level enforcement and monitoring.
- LibreOffice full macro behavior is not trusted: macro-bearing package parts
  are rejected before the binary is invoked.
